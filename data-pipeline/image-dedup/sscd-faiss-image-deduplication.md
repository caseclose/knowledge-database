# 图片查重怎么做：SSCD 特征 + FAISS 近邻搜索 + 并查集聚类

> 创建时间：2026-07-16 ｜ 最新更新：2026-08-23

## 背景

训练数据中经常存在大量重复或近似重复的图片（爬虫重复抓取、数据合并等）。直接用图片像素比对太慢且不准（缩放、裁剪、压缩后像素就变了），需要一种高效且鲁棒的去重方案。

核心思路：**给每张图片算一个"数字指纹"（SSCD 特征向量），用 FAISS 快速找最像的指纹，再用并查集把相似关系聚成组，每组只留一张。**

## 方案：四步去重流水线

```
1. 加载特征   每张图预提取 SSCD 特征向量，从 JSONL 或对象存储读取
2. 构建索引   用 FAISS 建立近邻索引（HNSW 或 IVF），支持秒级检索
3. 搜索聚类   每张图查 top-k 近邻 -> 阈值过滤 -> 并查集聚类成重复组
4. 去重保留   每组按策略保留一张（最高分辨率 / 第一个 / 最后一个）
```

### 第一步：SSCD 特征--图片的"数字指纹"

SSCD（Self-Supervised Compression and Detection）是一种自监督学习的特征提取方法，训练目标就是让相似图片的特征向量也相似。它对缩放、裁剪、压缩等变换鲁棒，比直接比像素靠谱得多。

特征向量提前算好，存储方式有两种：

| 存储方式 | 说明 |
|----------|------|
| 内嵌 JSONL | 特征直接写在 `feature` 字段里，读取即可用 |
| 对象存储 | JSONL 里有特征文件路径，需要下载后使用；支持多线程并发下载 + 本地缓存 |

### 第二步：FAISS 索引--"指纹速查本"

百万级图片两两比较是 O(N²) 复杂度（百万级要算万亿次），不可行。FAISS 建索引后，查"跟我最像的 200 个是谁"可以秒出。

支持两种距离度量：

| 度量 | 原理 | 适用场景 |
|------|------|----------|
| L2 | 欧氏距离，距离越小越像 | 通用默认 |
| cosine | 先 L2 归一化，再用内积 | 特征分布差异大时更稳定 |

索引类型由 `index_string` 控制，主要有两种：

#### HNSW（内存够就用这个）

HNSW（Hierarchical Navigable Small World）是一张分层图索引，核心思想是在"关系网"里跳跃式找最近邻。

想象一个分层社交网络：
- 每个指纹是一个节点，跟自己最像的 M 个指纹连边（`M=32` 即每个节点 32 条边）
- 图是**分层**的：顶层稀疏（节点少、边长，快速跨越远距离），底层密集（节点全、边短，精确定位）

查找时像坐地铁：
1. 先上顶层，大步跳，快速接近目标区域
2. 逐层往下走，越走越精确
3. 到最底层，精确定位到最近的那些

关键参数：

| 参数 | 含义 | 典型值 |
|------|------|--------|
| `M` | 每个节点的连接数，越大越准但越费内存 | 32 |
| `efConstruction` | 建图时的努力程度，越大图越密越准 | 1000 |
| `efSearch` | 查询时的搜索范围，越大查得越仔细越准 | 1000 |

内存占用：`(d * 4 + M * 2 * 4)` bytes/vector。

#### IVF（内存不够时用）

IVF（Inverted File）是分桶索引，核心思想是先聚类分区，只在自己所在和邻近的桶里找。

想象图书馆找书：
1. 先按主题分区（K-Means 聚类），每区有个"区长"（聚类中心）
2. 查找时先问哪个区长跟自己最像，只去那个区翻
3. `nprobe` 控制翻几个区，翻得多更准但更慢

需要先 `train()` 学出分区。配合 PQ（Product Quantization）可以压缩向量，大幅省内存但有精度损失。

#### 索引选择对比

| | HNSW | IVF |
|--|------|-----|
| 原理 | 分层图，跳跃搜索 | 聚类分桶，桶内搜索 |
| 速度 | 很快 | 快 |
| 精度 | 高 | 取决于 nprobe |
| 内存 | 大 | 小（可配 PQ 压缩） |
| 需要训练 | 否 | 是 |

选择建议参考 [FAISS 官方指南](https://github.com/facebookresearch/faiss/wiki/Guidelines-to-choose-an-index#how-big-is-the-dataset)。

### 第三步：搜索 + 并查集聚类--"找相似的人，拉群"

这是去重的核心逻辑：

1. **批量搜索**：每个样本拿自己当 query，查索引中 top-k（默认 200）个最近邻，分批查询（默认 batch=2048）
2. **距离转相似度**：
   - cosine 模式：内积值即为相似度
   - L2 模式：`similarity = 1 - distance / max_distance`
3. **阈值过滤**：相似度 >= `threshold`（默认 0.9）才算重复
4. **并查集聚类**：关键设计--
   - 如果 A～B 且 B～C，则 A、B、C 归入同一组，**即使 A 和 C 直接相似度低于阈值**
   - 实现了传递性聚类，避免漏判（就像朋友的朋友也是同一圈子）
5. **只记录最优配对**：每个样本只保留相似度最高的那一个匹配对，避免存储大量冗余信息

### 第四步：去重保留策略

每个重复组只保留一个，其余移除：

| 策略 | 说明 |
|------|------|
| `highest_resolution`（默认） | 保留像素最多的那张，需要 JSONL 中有图片路径 |
| `first` | 保留组内第一个（按索引排序） |
| `last` | 保留组内最后一个 |

## 用法示例

```bash
python3 dup_detect_faiss.py \
  --input ./jsonl_files/data.jsonl \
  --output ./results/data_cleaned.jsonl \
  --removed ./results/data_removed.jsonl \
  --index-string "HNSW32,Flat" --efc 1000 \
  --threshold 0.9 --topk 200 \
  --keep highest_resolution \
  --download-from-cos --max-workers 256 \
  --similarity-pairs-file ./results/data_pairs.jsonl
```

### 关键参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--threshold` | 0.9 | 相似度阈值，越高越严格 |
| `--topk` | 200 | 每张图搜索的最近邻数量 |
| `--metric` | l2 | 距离度量（l2 / cosine） |
| `--keep` | highest_resolution | 保留策略 |
| `--index-string` | - | 索引类型，如 `HNSW32,Flat` |
| `--efc` | 1000 | HNSW 构建参数 efConstruction |
| `--efs` | 1000 | HNSW 搜索参数 efSearch |
| `--download-from-cos` | False | 是否从对象存储下载特征 |
| `--max-workers` | 32 | 并发下载线程数 |

### 输出文件

| 文件 | 内容 |
|------|------|
| `--output` | 去重后的数据 |
| `--removed` | 被移除的重复数据 |
| `--similarity-pairs-file` | 相似度对明细（按相似度降序，可用于人工抽检） |

## 工程细节

| 设计 | 原因 |
|------|------|
| 特征预提取 + 按需下载 | 避免每次去重都重新跑模型提取特征，COS 下载结果可缓存复用 |
| 批量搜索（batch=2048） | 单条查询 FAISS 调用开销大，批量摊薄开销 |
| 并查集而非两两配对 | 传递性聚类避免 O(N²) 两两比较，且不漏判间接重复 |
| 只记录最优配对 | 每个样本只留一个最像的，避免存储和写入大量冗余对 |
| 特征维度标准化 | 不同来源特征维度可能不一致，填充或截断到统一维度 |
| 索引可保存/复用 | 构建索引耗时长，保存到文件后下次直接加载 |

## 总结

| 要点 | 说明 |
|------|------|
| 特征 | SSCD 自监督特征，对变换鲁棒 |
| 索引 | HNSW（快准但费内存）或 IVF+PQ（省内存有损精度） |
| 聚类 | 并查集实现传递性聚类，A～B～C 则同组 |
| 保留 | 默认留最高分辨率，优先保质量 |
| 阈值 | 0.9 较严格，可按需调整 |

> **一句话：** 给每张图算 SSCD 指纹，用 FAISS 索引秒查 top-k 近邻，并查集把相似关系聚成重复组，每组按分辨率保留最优一张。
