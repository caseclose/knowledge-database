# 代码渲染驱动的信息图数据工厂：LLM 写代码 → 浏览器渲染 → DOM 级标注

> 创建时间：2026-07-28 ｜ 最新更新：2026-07-28

## 背景

要为文生图（T2I）和图像编辑训练造"信息图 / 网页 / PPT"这类**结构化设计图**数据，传统路线有两个死穴：

- **caption 靠 VLM 猜**：密集文字的图，VLM 必然认错、漏字、坐标不准。
- **编辑对靠 GroundingDINO + SAM + inpainting 造**（AnyEdit / ImgEdit / Step1X-Edit 这一派）：只能做自然图像的物体增删改，非编辑区必有像素漂移，mask 不精确。

核心思路：**让 LLM 写代码（HTML/CSS/SVG/图表库）→ 浏览器渲染成图 → 从 DOM 直接读出每段文字的内容、bbox、字号、颜色、层级做标注。** 一份代码同时供给两种数据：T2I 图文对、图像编辑三元组。

## 为什么这条路成立

两个别人拿不到的优势：

| 优势 | 说明 |
|------|------|
| **代码 = 图像的完整符号表示** | 渲染时从 DOM 直接拿到每段文字的内容、bbox、字号、字重、颜色、层级。caption 不用 VLM 猜，文字 bbox 可直接用于 layout-control 训练 |
| **改一行代码重渲染 = 像素级完美对齐的编辑三元组** | 非编辑区严格一致，mask 由 DOM bbox 精确给出，指令由代码 diff 自动生成。一份代码派生几十个编辑对，边际成本近零 |

**复利效应（最关键的工程决策）**：产物必须**持久化代码原文**。以后换分辨率、换风格、派生新编辑算子，都不用重跑 LLM，直接重渲染。

相关工作定位：
- **CoSyn**（ACL 2025）已验证"LLM 写代码→渲染→用代码当上下文出标注"可行，但服务 VLM 理解、产出 QA，不是生成侧数据。
- **Qwen-Image** 的中文渲染依赖"程序化替换 PPT/UI 模板占位文字"，但停在**规则替换模板**，没到 LLM 自由生成代码——这是增量空间。
- **结构化设计图的编辑数据是空白**，而"改海报文案、换配色、改图表数值"是产品最高频的真实需求。

## 流水线分层（L0–L6）

```
L0 资产层    字体/图标/插画/配色/版式库，落共享盘，@font-face 引用
L1 内容层    主题 × persona 采样出结构化内容 spec（标题/要点/数据/KPI）
L2 代码层    LLM 写参数化模板/组件 + 程序 N 倍扩增
L3 渲染层    Playwright 浏览器池多进程渲染，DPR=2，注入 JS 导出 DOM 元数据
L4 质检层    DOM 级门禁 + OCR 回读 + 去重 + 美学打分
L5 标注层    Range API 抽四档 bbox → layout IR → 分层 prompt
L6 真实化    透视贴屏/印刷质感/JPEG 压缩，消除渲染"塑料感"（阶段二）
```

### L0 资产层：字体是第一优先级

设计图数据的成败，很大程度取决于字体资产。要点：

- **规模**：中文 20–40 个字族，覆盖黑体/宋体/楷体/圆体/手写/书法/展示体，尽量全字重；英文从 Google Fonts 拉几百个。字族数量与类别覆盖是硬指标（支撑 prompt 级字体控制）。
- **字体元数据表**：每个字体登记类别、风格标签、字重、字符集覆盖，以及**中文自然语言别名列表**（宋体/衬线体/serif/报刊体 指向同一族）。caption 生成时从别名表随机采样说法，避免模型只认死一种表述。
- **接入方式（主）**：CSS `@font-face` 引用共享盘字体，渲染结果与机器环境**解耦、跨机一致**，字族成为可控采样变量。
- **接入方式（兜底）**：自建 `fonts.conf` + `FONTCONFIG_FILE` 指向，让 `fc-list` 也能看到，避免 Mermaid/ECharts 走系统回退出豆腐块。注意 `<cachedir>` 必须指向各机器**本地** `~/.cache/fontconfig`，共用缓存会打架。
- **静态资源服务**：Chromium 用 `file://` 加载 `@font-face` 会撞 CORS，起一个本地静态 server（如 `localhost:9800`）统一提供字体/图标/插画，页面走 http 引用。
- **缺字校验（硬门禁）**：用 fontTools 查 cmap，渲染前确认每个字符在所选字体里有字形。豆腐块会成规模污染数据。
- **授权**：Noto CJK / 思源 / 霞鹜文楷是 OFL 可放心用；商用字体条款需逐个确认，`LICENSES.md` 登记来源。

### L2 代码层：防分布坍缩

纯 LLM 逐条写成本高失败率高，纯规则模板多样性见顶。**混合策略**：LLM 生成参数化模板/组件，程序做 N 倍扩增。防坍缩三件套：

- 模板**使用次数设上限**
- 设计变量随机化
- 布局签名去重

### L4 质检层：DOM 级检测是独门优势

在浏览器里做检测，比图像级质检又准又快：

| 检测项 | 方法 |
|--------|------|
| 文字溢出 | `scrollWidth > clientWidth` |
| 元素遮挡 | 元素矩形相交 |
| 字号过小 | 低于阈值直接丢 |
| 对比度不足 | WCAG 对比度门禁 |
| 文本一致 | OCR（PaddleOCR）回读一致率 |
| 重复 | pHash + 布局签名去重 |

**最小字高按最终输出分辨率折算**——1024 分辨率下 VAE 重建不出的小字，等于教模型画乱码。

## L5 标注层：像素级精细 bbox

### 四档抽取粒度

用 Range API + `getClientRects()` 拿**字符级 / 词级 / 行级 / 元素级**四档 bbox。中文段落换行后每行一个矩形，只存元素级会把整段圈成一个大框，对 grounding 无用。

**存储策略**：默认落行级 + 元素级；字符级只对标题、数字、KPI 等关键元素开启（密集中文图上千个字符框，全量存会让标注比图还大）。需要全量字符级时从持久化代码重渲染补齐。

每段文字的字段：

```jsonc
{
  "text": "季度营收同比增长 32%",
  "level": "line",                    // char | word | line | element
  "bbox": [x1, y1, x2, y2],           // 最终输出图的像素坐标
  "bbox_norm": [0.12, 0.08, 0.63, 0.14],
  "font_family_declared": "SourceHanSansSC",
  "font_family_actual": "Source Han Sans SC",  // 实际生效字体，可能因缺字回退
  "font_category": "黑体", "font_aliases": ["无衬线", "sans-serif", "黑体"],
  "font_weight": 700, "font_size_css": 48, "font_size_px": 96,  // 输出图上实际字高
  "color": "#1A1A1A", "bg_color": "#FFFFFF", "contrast_ratio": 15.3,
  "z_index": 2, "visible_ratio": 1.0,  // 被裁剪/遮挡后的可见比例
  "role": "title"                      // title | subtitle | body | label | caption | number
}
```

### 三个必须处理的坑

| 坑 | 后果 | 处理 |
|----|------|------|
| **坐标空间不统一** | DPR=2 渲染 + resize 有多个缩放系数 | 统一折算到最终输出图像素坐标，同时存归一化版本 |
| **实际字体 ≠ 声明字体** | 缺字回退、字重合成让实际渲染偏离 CSS 声明 | `document.fonts.check()` + Range 测量交叉验证，标注记**实际生效**的 |
| **可见性未校正** | 被 `overflow:hidden` 裁掉或被盖住的文字，DOM 照样返回完整 bbox | `elementFromPoint` 采样算 `visible_ratio`，过低直接剔除 |

### 分层 Prompt：同一张图产出多个变体

| 档位 | 内容 | POC 配比 |
|------|------|----------|
| T0 极简意图 | "一张关于新能源汽车销量的信息图"（10–20 字） | 15% |
| T1 短描述 | 主题 + 风格 + 主要文字（50–80 字） | 15% |
| T2 长描述 | 完整版式/配色/字体/各区块内容与相对方位，不出现数字坐标（200–500 字） | 30% |
| T3 半结构化 | 自然语言 + 关键元素精确约束（"标题『XXX』思源黑体 Bold 96px 位于 (120,80)–(960,200)"） | 30% |
| T4 全结构化 | 所有文字元素完整字段清单 | 10% |

全结构化占比不宜高，否则模型偏向依赖坐标。

**dropout 的正确实现（关键）**：**不能对已成文的自然语言做字符串删除**，那会把句子删得语法破碎、前后矛盾。正确做法是从 DOM 抽出的 **layout IR** 出发，按不同 dropout 配置分别**渲染出多个自洽的 prompt 变体**。layout IR 因此必须持久化，它是所有 prompt 形态的唯一真源。

- **dropout 维度**：字段级（bbox/font/size/color 各自独立按概率丢）、元素级（只约束部分元素）、粒度级（精确坐标 → 方位词 → 完全不提）。
- **坐标表述多样化**（真实用户不说像素值）：绝对像素、归一化、九宫格方位词（"左上区域"）、相对关系（"标题下方""与图表左对齐"）。后两类占比要够高。
- **评测分开测**：无坐标 prompt 的生成质量，与有坐标 prompt 的位置遵循度（OCR 检测框 vs 给定 bbox 的 IoU）。

**顺带白捡的两样**：
- **空间指代编辑指令自动生成**："把右下角那张卡片的标题改成 X"——直接从 DOM 拿，不用 GroundingDINO+SAM。
- **bbox × OCR 闭环校验**：OCR 检测框与 DOM bbox 的 IoU 低于阈值即判定渲染异常，比单看文本一致率更能抓布局 bug。

## 受控变量对照组：代码渲染的独有玩法

同一份内容、同一个版式，**只改一个变量**（字体族 / 主题色 / 字重 / 栅格列数）批量渲染成一组。模型能直接对比出单变量变化对应的图像变化——这是学会**解耦控制**最有效的信号；同时这组图天然就是完美对齐的编辑三元组。成本只是改一个 CSS 变量重渲染。

## 编辑算子库

每个算子 = 代码变换函数 + mask 计算 + 指令模板集。产出 before/after/mask/指令，指令由 LLM 口语化。

| 类别 | 算子举例 |
|------|----------|
| 文本类 | 改标题/正文/数字、中↔英切换、字号字重、字体族替换 |
| 颜色类 | 主题色替换、明暗模式切换、单元素改色、渐变 |
| 布局类 | 元素位置互换、对齐方式、增删条目/卡片、栅格列数 |
| 图表类 | 数值改动、图表类型切换、系列增删、坐标轴范围 |
| 元素类 | 图标替换、logo 增删、图片替换、水印、圆角阴影 |
| 风格类 | 扁平 ↔ 拟物 ↔ 玻璃拟态 |

## 模型选型：双档分阶段

写信息图代码的难点不是算法复杂度，是审美与版式多样性，而多样性主要来自 **prompt 侧的 persona/风格采样**，不是靠模型规模堆出来的。所以大模型只用在决定质量上限的"模板作者"档，批量环节用小 MoE 压成本。

| 档位 | 模型形态 | 职责 |
|------|----------|------|
| 模板作者 | 大模型（如 397B-A17B-FP8，TP8），几千次调用产出 500–2000 个参数化模板 | 决定质量上限 |
| 批量工人 | 小 MoE（如 35B-A3B-FP8，单卡多副本），激活吞吐极高 | 承担 90% 调用量（内容 JSON、指令口语化、caption 润色） |

**bake-off 先验证再定档**：同一批 50 prompt（信息图/落地页/PPT，中英各半）跑候选模型，比**渲染成功率 / DOM 质检通过率 / 美学分（HPSv3 + cvtg-aesthetic）/ 布局签名多样性**四个硬指标。若小模型质检通过率与大模型差距不显著，直接砍掉模板作者档，全部算力跑量。

## 已识别风险

| 风险 | 应对 |
|------|------|
| Chromium 系统依赖装不上 | 先 `playwright install-deps`；失败退到 conda-forge chromium 或自带 chromium 的 puppeteer |
| 模板痕迹导致分布坍缩 | 使用次数上限 + 变量随机化 + 持续注入新模板 + 布局签名去重 |
| bbox 标注失真 | 坐标空间不统一 / 实际字体偏离 / 遮挡未校正，任一出错都会产出大量"看似正确"的脏标注，必须用 OCR IoU 闭环抽查 |
| 素材版权 | 字体走 OFL、图标按 license 过滤、配图优先本地 T2I 生成 |

> **一句话：** 让 LLM 写代码、浏览器渲染成图，从 DOM 直接读出文字的内容/bbox/字号/颜色做无损标注；改一行代码重渲染就得到像素级对齐的编辑三元组；持久化代码原文即可零成本再派生，是造结构化设计图数据的高杠杆路线。
