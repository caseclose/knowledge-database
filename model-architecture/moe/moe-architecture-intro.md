# MoE（混合专家）架构介绍

MoE（Mixture of Experts，混合专家）是当下大模型「参数量暴涨但算力可控」的核心手段。核心思想一句话：**把一个大 FFN 拆成很多个「专家」，每个 token 只激活其中少数几个**，从而在总参数量很大的同时，单 token 的实际计算量（激活参数）很小。代表：Mixtral、DeepSeek-V3、Qwen3、Llama 4、GPT-oss。

## 背景：为什么要 MoE

稠密（dense）模型每个 token 都要过全部参数，参数量和算力**线性绑定**。MoE 用**稀疏激活**解耦二者：

| | 总参数量 | 单 token 激活参数 | 算力 |
|---|---|---|---|
| Dense | N | N | 高 |
| MoE | 远大于 N | 只有一小部分 | 低 |

例：DeepSeek-V3 总参 671B，但每 token 只激活约 37B。

## 结构：把 FFN 换成「路由器 + 专家组」

Transformer 每层的 FFN 被替换为：

```
          ┌──────────────────────────────┐
token ──► │ Router / Gating（打分 + top-k）│
          └───────────────┬──────────────┘
                          │ 选中的 k 个专家
        ┌────────┬────────┼────────┬────────┐
     Expert1  Expert2   ...      Expert_k   （每个专家是一个小 FFN）
        └────────┴────────┼────────┴────────┘
                          │ 按门控权重加权求和
                          ▼
                       输出
```

### 1. 路由（Routing / Gating）

对每个 token 的隐藏向量 `x` 与每个专家算亲和度分数（`s = x·W_e`），取分数最高的 **top-k** 个专家，用 softmax 归一化其分数作为加权权重：

```
scores = x @ W_router.T          # [num_experts]
idx    = topk(scores, k)         # 选 k 个专家
weight = softmax(scores[idx])    # 门控权重
y      = Σ weight_i · Expert_i(x)
```

- **top-1 / top-2** 是最常见配置（Mixtral 8×7B 用 top-2）。
- 只有被选中的专家参与前向/反向，其余不计算。

### 2. 负载均衡（Load Balancing）

MoE 最大的坑是 **routing collapse**：路由退化到只用少数几个专家，其余闲置，既浪费参数又降效率（专家并行时更糟）。两类解法：

- **辅助损失（auxiliary loss）**：GShard/Switch 用一项额外 loss 惩罚不均衡，逼路由把 token 摊平。缺点：太强会**损害主任务性能**。
- **无辅助损失（aux-loss-free，DeepSeek-V3）**：给每个专家一个**动态偏置 `b_i`**，只在 top-k **选择**时加到分数上（`s_i + b_i`），但**不进入最终门控权重**；每步根据专家负载调整 `b_i`（过载减、欠载加）。既均衡又不牺牲性能。

### 3. 现代改进：细粒度专家 + 共享专家（DeepSeekMoE）

| 改进 | 做法 | 好处 |
|------|------|------|
| **细粒度专家** | 把专家切得更小更多（如 64+ 个，每个 1/4~1/8 大小），相应提高 top-k（如 6~8） | 专家组合数指数级增加，专业化更强 |
| **共享专家** | 隔离若干**始终激活**的专家承载「通用知识」 | 让路由专家专注差异化知识、减少冗余 |
| **设备约束路由** | 先选 top-M 设备、再在其中选 top-k 专家 | 控制跨设备通信，利于超大规模并行 |

> 趋势：细粒度 + 高专家数已成主流；**共享专家可选**——DeepSeek、Llama 4 用，Qwen3、GPT-oss 不用。Llama 4 甚至用 top-1 路由 + 1 个共享专家。

## 优缺点

| 优点 | 缺点 / 代价 |
|------|------------|
| 总参数大、激活小，性价比高 | 显存占用按**总参数**算（要放下全部专家） |
| 训练/推理更省算力 | 路由不均衡、训练不稳，需负载均衡 |
| 专家专业化，能力更强 | 专家并行的通信开销、工程复杂 |

## 总结

> **一句话：** MoE 把稠密 FFN 换成「路由器 + 一组专家」，每个 token 只经 top-k 个专家实现稀疏激活，从而解耦「总参数量」与「单 token 算力」；关键工程是负载均衡（辅助损失 → DeepSeek 的无辅助损失动态偏置），现代改进是细粒度专家 + 可选共享专家。
