# 如何让纯文本大模型"看懂"图片：结构化 Caption Prompt

## 背景

纯文本大模型（GLM、Llama 等）无法接收图像。常见做法是用多模态模型（VLM）先生成文字描述（Caption），再传给文本模型。

但常规 Caption 存在三个致命缺陷：

1. **OCR 遗漏**：忽略代码块、微小文字、水印、按钮文本，技术文档截图失去核心价值。
2. **视觉细节丢失**：不描述红框、箭头、高亮色块、界面布局，文本模型无法理解"重点在哪里"。
3. **主观幻觉**：模型"看图编故事"，添加图片中不存在的内容，误导下游任务。

## 解决方案

### 核心思路

用结构化思维链（CoT）强制 VLM 按固定框架输出：

1. **先搭骨架**：全局布局概览
2. **再填血肉**：按区域做"视觉特征 + 完整 OCR"交织描述
3. **最后点睛**：专门提取视觉强调（红框、高亮）和边缘元数据
4. **绝对约束**：强制客观中立，杜绝幻觉

### Prompt 模板

可直接作为 System Prompt 或 User Prompt 发送给 VLM（Qwen-VL、GPT-4o、Claude 3.5 Sonnet）：

```text
你是一个极其严谨、细致的图像分析专家。你的任务是为这张图片生成一份信息密度极高、绝对客观的"终极描述"。这份描述将直接输入给一个完全看不见图片的纯文本 AI，因此你必须确保它通过你的文字就能在脑海中 100% 重构出这张图片的所有细节。

请严格遵守以下原则：
1. 绝对客观中立：只描述你看到的客观事实，绝不添加主观评价、情感色彩或编造图片中不存在的内容（防幻觉）。
2. 零遗漏：所有的文字（包括微小文字、代码、水印）、所有的视觉元素（颜色、布局、图标、标注框）都必须被记录。
3. 结构化输出：必须严格按照下方的 Markdown 模板进行输出。

---
请按照以下结构输出描述：

#### 1. 全局概览
- **图片类型**：（例如：网页截图、UI 界面、数据图表、实景照片等）
- **核心主题**：（用一句话客观概括图片展示的主要内容）
- **整体布局**：（详细描述画面的空间划分，例如："画面分为左右两栏，左侧为窄边栏，右侧为宽正文区"）

#### 2. 详细内容拆解（按从上到下、从左到右的阅读顺序）
（请将画面划分为几个逻辑区域，逐个区域进行"视觉+文字"的交织描述）
- **[区域名称，如：顶部导航栏 / 左侧边栏]**：
  - **视觉特征**：（描述背景色、边框、图标形状、选中状态的高亮色等）
  - **完整文字转录**：（逐字提取该区域所有文字，保持原有的层级关系，如标题、列表项）
- **[区域名称，如：右侧正文区]**：
  - **视觉特征**：（描述段落排版、代码块的背景色、字体颜色变化等）
  - **完整文字转录**：（提取所有正文。如果是代码，必须使用 Markdown 代码块格式完整保留代码内容和缩进；如果是公式，请描述其结构）
（如有更多区域，请继续按此格式添加）

#### 3. 视觉强调与特殊标注（关键细节）
（专门描述画面中用于引导视线的特殊元素）
- **颜色高亮**：（例如："标题中的 'pkill -f' 使用了红色字体和浅灰色背景"）
- **标注框/箭头**：（例如："画面右侧有两个红色的矩形线框，分别圈住了两个代码块右上角的 'bash' 标签"）
- **图标与 Logo**：（描述图标的形状、颜色及位置，如右上角的蓝色三角形角标及内部的白色动物剪影）

#### 4. 边缘信息与元数据
- **水印/页眉页脚**：（提取画面边缘的所有微小文字、Logo 或水印内容）
- **其他细节**：（如滚动条位置、鼠标光标位置、界面状态如"加载中"等，如有）

---
**最后检查**：在输出前，请自我核对是否遗漏了任何文字或视觉细节？是否保持了客观中立？确认无误后输出。
```

### 配置建议

| 项目 | 推荐值 | 说明 |
|------|--------|------|
| VLM（商业） | GPT-4o / Claude 3.5 Sonnet | 细节还原、OCR 极佳 |
| VLM（开源） | Qwen2-VL-72B / InternVL2 | 中文 OCR 开源最强 |
| Temperature | 0.1 ~ 0.3 | 低温度抑制"创造力"，保证客观 |
| Top_P | ~0.8 | 配合低温度使用 |

### 精简版 Prompt（快速截图描述）

当只需要快速描述一张截图给纯文本模型时，用这个短版本即可：

```text
请客观描述这张图片，按以下格式输出：

1. 图片类型和主题：这是什么类型的图片，展示了什么
2. 布局：画面的空间划分（左右分栏、居中、全屏等）
3. 完整文字：逐字提取所有可见文字，包括标题、按钮、菜单、代码块内容
4. 视觉强调：红框、高亮、箭头、颜色标记等用于引导视线的元素

只描述看到的客观事实，不要编造或推测。
```

> 完整版适合技术文档截图、UI 设计稿等需要无损还原的场景；精简版适合日常截图快速沟通。

下游文本模型的输入格式：

```text
以下是某张图片的详细结构化描述。请基于此描述回答我的问题：

[粘贴 VLM 的输出]

我的问题是：[用户的问题]
```

## 总结

| 方式 | 效果 |
|------|------|
| 常规 Caption | "技术博客截图，讲了 pkill 和 fuser，有代码和红框" — 信息丢失严重 |
| 结构化 Caption | "右侧正文区含深色代码块 `pkill -f python`，两个红色矩形框圈住 bash 标签" — 文本模型可精确理解 |

> **一句话：** 用结构化 CoT Prompt 强制 VLM 按"全局布局 -> 区域交织 -> 视觉强调 -> 元数据"四步输出，再喂给纯文本模型，即可实现图像信息的无损传递。
